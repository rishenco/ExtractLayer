3,133 repositories searched. The primitive is commoditised; the gap has moved to everything around the call.

The short version

The primitive is finished — three lines against a provider API, wrapped by a dozen mature libraries.

The practice has not caught up. Of the 2,150 repos here that actually do LLM extraction, 3.0% show any named extraction library — no instructor, no outlines, no BAML, no LangChain structured output. The long tail calls provider APIs directly and parses by hand. The most-used package after the providers themselves is json_repair, which exists to patch malformed model output.

So: solved at the head, re-implemented from scratch almost everywhere else — and largely without the parts that make extraction trustworthy. Median star count is 2.

The space is young and rebuilt continuously: 1,712 of the relevant repos were created in 2025 or later and 1,117 (52%) in 2026 alone. Only 26 are archived. Python holds 60% (1,291 repos), TypeScript 225, Jupyter 175, JavaScript 95, Rust 56, Go 52, HTML 48; 101 report no language.

How the call is actually written 6 shapes

Six distinct API shapes have emerged for the same operation. Every snippet is copied from that project's own README.

01 · Patch the provider SDK

The call site stays familiar; one extra argument carries the schema. This is instructor, the shape most others are measured against.

client = instructor.from_provider("openai/gpt-4o-mini")
user = client.chat.completions.create(
    response_model=User,
    messages=[{"role": "user", "content": "John is 25 years old"}],
)
02 · Schema-first method

The literal llm(schema, text) signature. sibila:

model = Models.create("llamacpp:openchat")
model.extract(Info, "Who was the first man in the moon?")
03 · Type-first function

No schema class at all — the return type is the schema. marvin:

result = marvin.extract("i found $30 on the ground and bought 5 bagels for $10",
                        int, instructions="only USD")
04 · Examples instead of a schema

Few-shot examples define the shape, and every extracted field is grounded back to a source span. langextract:

result = lx.extract(text_or_documents=input_text, prompt_description=prompt,
                    examples=examples, model_id="gemini-3.5-flash")
05 · Declarative document model

You attach what you want to a document rather than calling an extractor. contextgem:

aspect = Aspect(name="Term and termination",
                description="Clauses on contract term and termination")
concept = BooleanConcept(name="NDA check", description="Is the contract an NDA?")
document.add_aspects([aspect]); document.add_concepts([concept])
06 · Schema as a separate language

The schema lives in its own DSL file and compiles to a typed client. BAML:

from baml_client import b
resume = b.ExtractResume(resume_text)

The trend across the head of the corpus runs away from prompt strings and toward a typed function boundary. BAML goes furthest by moving the prompt out of the host language entirely — the only approach here that makes the prompt diffable and testable on its own.

The head does what the tail doesn’t

Reading the docs of 24 landmark projects and recording what each supports: 11 of 24 retry on validation failure, against 7% corpus-wide; 5 of 24 ground fields to source, against 9%. Retries are near-universal in the serious libraries — instructor, pydantic-ai, guardrails, marvin, magentic, mirascope, TypeChat and contextgem all re-ask on failure — and essentially absent everywhere else. The capability exists; it isn’t reaching the people rebuilding this by hand.

Grounding splits by tier rather than by quality. Document tools carry it because they must — unstructured, unstract and sparrow all trace values back to a page or region — while in the plain-text tier only langextract and contextgem do. For any extraction a human must audit, that is the difference between a reviewable output and an unfalsifiable one.

One design note worth recording: BAML, the most opinionated project in the set, does not use constrained decoding or provider structured outputs. It generates freely and parses with its own error-tolerant parser, on the argument that a good parser beats a constrained decoder. That is a live disagreement at the top of this space, not a settled question.

Method & limits

GitHub repository search across 106 queries in four families: mechanism vocabulary, extraction vocabulary, modality, and vertical. Star-sliced queries (stars:20..80, stars:81..400) reached past the 1,000-result ranking cap. 22 landmark projects that keyword search missed were backfilled by exact-name lookup and are tagged landmark in the data rather than attributed to a query. Every repo was then validated by fetching its README from raw.githubusercontent.com, retrying transient failures across twelve filename variants: 3,027 of 3,133 returned content, and the remaining 103 were confirmed to 404 on every variant. Star counts were spot-checked against fresh API queries and matched exactly.

  • 106 repos have no usable README — 103 confirmed 404 on every filename variant, 3 whitespace-only. They keep description-and-topics signals only.
  • Everything except stars, dates and languages is a keyword measurement. Domain, capability, mechanism and layer are regex signals over README and manifest text — they measure what a repo says, not what it does. Where a loose pattern inflated a number, both figures are reported so the inflation stays visible: mention-of-Pydantic 34% vs authored-BaseModel 5%; loose-local 41% vs actual-local-runtime 25%.
  • Layer assignment is ~60% accurate. Hand-labelling a fresh 30-repo sample against the final classification gives 18/30; pooling the two held-out samples taken after tuning gives 38/60 — call it 60% ± 9. Failures are not random: vertical apps read as generic primitives, and demos read as products.
  • The relevance filter carries roughly 10% false positives. Three of those same 30 are not LLM data extraction at all — a text-guided speech separation model, an ISO-8583 payments simulator, and a Go serialization library — each matching on shared vocabulary.
  • Coverage is broad but not saturated. 82% of repos were surfaced by exactly one query. Keyword search has a systematic blind spot: an initial landmark check found only 17 of 49 known projects, though roughly a third of those "misses" were stale aliases of renamed repos (instructor-ai → 567-labs, outlines-dev → dottxt-ai, and four others) rather than true gaps. After resolving renames and backfilling, 39 of 49 were present.
  • Not measured at all: schema versioning, contributor counts, and whether any project's extraction is actually accurate. No claim here rests on them.
